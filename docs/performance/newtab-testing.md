# 新标签启动验证

本次使用 Chrome for Testing 151.0.7922.34，通过独立测试配置加载真实解压扩展。没有模拟浏览器 API，没有更改日常浏览器配置。

对照版为远端最新提交 `bccb646`，优化版为当前工作区，包含本轮及前一轮优化。均使用默认配置、关闭自动聚焦，每种场景各测 8 次，排除首次安装迁移。

## 本机测量

单位为毫秒，中位数。计时从页面导航开始，不包含用户点击浏览器「+」到开始导航的浏览器 UI 调度时间。

| 场景 | 指标 | 原版 | 优化版 |
| --- | --- | ---: | ---: |
| 连续打开 | 输入框出现 | 55.8 | 49.2 |
| 连续打开 | 搜索引擎出现 | 55.8 | 54.5 |
| 连续打开 | 网站卡片出现 | 53.1 | 54.5 |
| 停止后台后打开 | 输入框出现 | 87.5 | 60.3 |
| 停止后台后打开 | 搜索引擎出现 | 87.5 | 73.4 |
| 停止后台后打开 | 网站卡片出现 | 84.7 | 73.4 |

“停止后台”指在测试浏览器中调用 CDP 停止 Service Worker；没有重新启动浏览器或清空磁盘缓存。结果不等于浏览器完整冷启动。单机少量样本存在噪声，不能推断所有设备都有相同比例的收益。

原版与优化版均通过 16/16 次输入保留检查，无页面 JS 异常。完整数据见 [测量数据](newtab-benchmark-2026-11-07.json)。

其中一次停止后台后的加载顺序：

- 原版：68.7ms 请求后台准备 → 84.6ms 网站卡片 → 89.3ms 输入框和引擎。
- 优化版：60.8ms 输入框 → 73.4ms 引擎和网站卡片 → 75.2ms 请求后台维护。

## 自动复测

脚本使用 Playwright Core 和其匹配的 Chromium / Chrome for Testing。将 `PLAYWRIGHT_MODULE` 指向已有安装的 `playwright-core/index.mjs`，无需修改项目依赖。浏览器需先通过对应 Playwright CLI 安装：

```sh
node /path/to/playwright-core/cli.js install chromium
pnpm build
PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs \
  node scripts/benchmark-newtab.mjs .output/chrome-mv3 /tmp/newtab-result.json
```

将扩展目录换成旧版的构建目录，即可对比。顺序执行两版，保持机器负载和测试数据一致。脚本会创建、关闭并清理独立浏览器配置，不接触日常浏览器。设置 `HEADED=1` 可显示测试窗口。

## 自己从「+」体验测试

1. 执行 `pnpm build`。在 Chrome 的 `chrome://extensions` 开启开发者模式，选择“加载已解压的扩展程序”，选项目 `.output/chrome-mv3` 目录；已加载则点刷新。
2. 连续点击「+」打开约 10 次，观察主题和默认页签是否闪动。立即输入一段文字，检查后续图标、引擎、背景出现时，文字和焦点是否保留。
3. 分别测试自动聚焦开、关。关闭时浏览器地址栏保持原有行为；开启时检查输入是否进入页面搜索框。本次自动计时仅覆盖关闭状态。
4. 分别将默认页签设为常用、书签、历史，以及“上次打开”。确认当前页签先可用，未打开的功能不会抢占首屏工作。
5. 用后台停止后的自动测试和浏览器完全退出后的手动测试区分两种冷启动。不要通过一直打开后台 Service Worker 的 DevTools 来测后台休眠启动，因为调试连接会影响它的生命周期。

若要看瀑布图，可在新标签页打开 DevTools 的 Performance，录制页面重载；对比主线程任务、FCP、输入框出现与后台请求的顺序。重载录制用于排查加载链路，不能替代从「+」打开的端到端体验测试。

## 大数据压力测试（2026-11-07）

使用当前优化版、真实扩展 API、独立浏览器配置，每档 3 次连续打开取中位数。测试构建副本将书签和历史权限提前授予，生产 manifest 不变。跨设备同步关闭。网站集中在根目录、书签集中在同一目录，历史全部生成于今天；统一采用内置 GitHub 图标，无截图及远程图片，因此不覆盖图片网络、解码与真实复杂目录的全部成本。

| 网站 / 引擎 / 书签 / 历史数量 | 输入框出现 | 网站卡片出现 | 切换书签并渲染目录 | 从常用页切换历史 |
| --- | ---: | ---: | ---: | ---: |
| 20 / 20 / 200 / 1,000 | 52ms | 58ms | 37ms | 124ms |
| 500 / 100 / 5,000 / 10,000 | 47ms | 79ms | 471ms | 163ms |
| 2,000 / 300 / 20,000 / 30,000 | 86ms | 196ms | 2,397ms | 299ms |

时间从导航或脚本触发页签点击开始，非物理鼠标点击「+」到显示的总耗时。页签耗时包含测试自动化观测开销。三次样本用于定位数量级问题，不宜据此推断精确线性关系。

极大数据档，常用页约生成 15,301 个 DOM 元素，启动观测到最长 114ms 的主线程任务。输入框先出现不能保证随后所有输入均无阻塞。书签页真实渲染 20,000 行，明显应引入可见范围渲染。历史页只渲染最多 2,000 条今日记录，不能将 299ms 理解为已处理并展示全部 30,000 条。

原始数据见 [大数据结果](newtab-volume-2026-11-07.json)。复测：

```sh
PLAYWRIGHT_MODULE=/path/to/playwright-core/index.mjs \
  node scripts/benchmark-newtab-volume.mjs .output/chrome-mv3 /tmp/newtab-volume.json
```
